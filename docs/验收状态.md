## 五、技术限制与已知取舍

- **SQLite 使用 WASM 构建**：不支持 WAL。当前为单进程单连接，写入串行化，未发现并发问题；若将来需要多进程并发访问，需要重新评估。
- **过时检测基于文件内容指纹**：文件被改写但语义未变时同样会提示复核，这是保守取向——宁可多提示，不把旧说明当事实。
- **未覆盖的依赖变化无法检测**：没有证据关联的代码变化不会触发提示，因此“无提示”不等于“记录准确”。
- **检索为关键词匹配**：未使用 FTS5 全文检索（WASM 构建虽有 FTS5，但中文分词效果有限）。项目功能数量增长后可能需要改进相关性排序。
- **理由只能来自用户表达或文档**：模型推测一律记为 `unknown`，这是产品承诺，不因查询体验而放宽。
