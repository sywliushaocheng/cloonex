# Cloonex 0.2.0 — portable history and reliable records

Move your local project knowledge to a new computer and tell historical verification apart from the current state of linked code. This remains an early local MCP tool; it does not provide cloud sync or automatic conversation capture.

## Install without cloning

Requires Node.js ≥ 20.11 and npm. No Git or local TypeScript compiler is needed:

```bash
npm install --global "https://github.com/sywliushaocheng/cloonex/releases/download/v0.2.0/cloonex-0.2.0.tgz"
cloonex --version
cloonex init
cloonex mcp-config --format json
```

If restoring existing history, skip `init` and follow the migration steps below. Codex can use the default TOML format and `cloonex install-skill`; other local stdio MCP clients use the same launch values in their own configuration format. The package and its `SHA256SUMS.txt` are built from this tag by the release workflow.

## Backup and restore

Old computer:

```bash
cloonex backup export --out "history.cloonex.gz"
```

Copy that file yourself. New computer:

```bash
cloonex backup inspect "history.cloonex.gz"
cloonex backup import "history.cloonex.gz" --data-dir "/absolute/path/to/CloonexData"
cloonex doctor
cloonex mcp-config --format json
```

IDs and relationships survive the move, including tasks, decisions, preferences, feature notes, evidence, review history and exported handovers. The archive uses a consistent SQLite snapshot and per-file SHA-256 checks. Import validates and upgrades a staged database, and refuses to overwrite or merge an existing library. Source code and client settings are not bundled. Archives are not encrypted. See [migration instructions](../migration.md).

## Record reliability

- Feature queries and task context check the linked files on demand. Responses distinguish `recordedReviewState` from current `freshness`, with a check time.
- Explicit verified re-review refreshes the code evidence baseline and keeps the previous baseline in review history. Identical checked statements refresh evidence without duplicating the statement.
- `supersede_statement` and `supersede_decision` retain the replaced records as history. Optional `topicKey` prevents accidental competing current records for the same declared topic.
- Lookup no longer replaces a human-readable feature title with its slug. `update_feature` explicitly updates titles and aliases.
- Finalization links all relevant features and closes the task in one transaction. `knowledgeMode: summary` is available for work that intentionally needs only a task summary.

## Find and manage knowledge

- `search_records` / `cloonex search` search task outcomes and verification text, feature names/aliases, decisions and current notes with matched-field explanations.
- `project_health` / `cloonex doctor` show broken project paths, unfinished tasks and missing knowledge links; file checks are optional.
- `project-move` relinks existing records to a relocated source repository without changing IDs.
- `rules` previews a project rule file; explicit `--apply` records its source fingerprint. Changed rule sources stop entering task context until rechecked.
- `labels alias` provides explicit scene/stack aliases; task `stack` also accepts an array of tags. No automatic semantic merging is performed.
- `project-group` associates related repositories for scoped search.
- `mcp-config --format json|connection|codex` generates installed local paths before database initialization.

## Upgrade and validation

Pause clients and keep a backup of the existing data directory before upgrading. Schema 3 uses additive tables/columns and preserves existing rows. Do not use an older binary against an upgraded library. Regenerate MCP settings and reinstall the Codex skill after upgrade. A client's `CLOONEX_DATA_DIR` environment value takes precedence over the local config file.

Regression tests cover the existing domain/MCP behavior, stale reads, re-review history, atomic finalization, explicit replacements, whole-library migration, damaged/unsafe archives, project rules, aliases and CLI restoration. CI also installs the packed product outside the checkout and verifies CLI, MCP, backup/import and skill installation on Windows/Linux and Node 20/22/24. Check the Actions results for the final release status.

Fingerprint changes signal a need to review, not a proven semantic error. macOS hardware and concurrent multi-process writes remain unvalidated. This release does not publish to the npm registry.
