# Cloonex 分享与分发指南

Cloonex 采用 MIT 许可证。公开源码不要求先发布到 npm，可从 GitHub 安装或分发本地安装包。

Cloonex 是通用本地 MCP stdio 服务，不绑定 Codex。安装后可配置到支持该连接方式的 AI 客户端；下文 `mcp-config` 与 `install-skill` 是 Codex 辅助命令，其他客户端参见[通用配置指南](mcp-clients.md#中文说明)。目前 Codex 已实测，其他客户端尚未逐一实测。

## 从 GitHub 安装

需要 Node.js ≥ 20.11 和 Git：

```bash
git clone https://github.com/sywliushaocheng/cloonex.git
cd cloonex
npm ci
npm install --global .
cloonex init
cloonex mcp-config --direct
cloonex install-skill
```

将 `mcp-config --direct` 输出的配置加入 Codex 配置文件（通常为 `~/.codex/config.toml`；设置了 `CODEX_HOME` 时使用该目录下的配置）。然后在 Codex 中审阅并信任 MCP 服务。

`--direct` 会使用当前 Node 与 Cloonex 的真实路径，适用于源码和本地安装包；无需从 npm 查找同名软件包。移动安装目录或更换机器后应重新生成配置。

如果不希望全局安装，可在源码目录执行：

```bash
node dist/src/cli.js init
node dist/src/cli.js mcp-config --direct
node dist/src/cli.js install-skill
```

升级源码安装时，在工作区干净且无本地分叉的情况下执行 `git pull --ff-only`、`npm ci` 和 `npm install --global .`，再重新安装技能。程序与个人数据目录独立，升级程序不需要删除知识库。

## 分发安装包

维护者运行：

```bash
npm run verify
npm pack
```

将生成的 `cloonex-<版本>.tgz` 分享给使用者。使用者执行（将文件名替换成实际版本）：

```bash
npm install --global ./cloonex-0.1.0.tgz
cloonex init
cloonex mcp-config --direct
cloonex install-skill
```

安装包包含编译产物、技能、README、许可证与验收状态文档，不包含源码目录、测试或个人知识库。安装运行依赖仍需访问 npm 源。仓库不附带预制 ZIP 或安装向导。

## 可选：发布到 npm

发布到 npm 是独立操作，需要有发布权限的 npm 账号，且须先确认目标包名可用。本指南不代表该包已发布。

```bash
npm run verify
npm pack --dry-run
npm login --registry=https://registry.npmjs.org
npm publish --registry=https://registry.npmjs.org --access public
```

若使用其他源或账号，请核对发布目标。只有确认包已发布且维护者身份正确后，才使用基于 npm 包名的安装和 `npx` 接入配置。

## 使用边界

- 项目约定、偏好与功能档案保存在本地；使用云端模型时，选入上下文的材料仍会发送给所用模型服务。
- SQLite 数据文件不自带加密，请按自己的设备和账户权限管理数据。
- Bug 修复任务不学习偏好；没有证据的历史原因标为未知。
- 文件指纹只覆盖已关联的证据。未提示过时不代表全部记录都准确。
- Windows 已有验证记录；macOS Apple Silicon、多进程并发写入和独立可执行文件尚未实机验证。
- 图形界面、团队协作、云同步和自动事件采集尚未实现。

更多验证记录与限制见 [验收状态.md](验收状态.md)。
